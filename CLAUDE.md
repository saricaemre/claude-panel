# Claude Panel

Before doing any work, say how you will verify it (see §4).

## 1. Proje

- Emre'nin Mac'inde (Apple Silicon, macOS) çalışan Electron masaüstü uygulaması. Üç ayrı Claude hesabını (İş, Max, Pro) tek pencerede, birbirine karışmadan kullanmak için.
- Her hesabın iki görünümü var:
  - **Yerel Code**: Claude Code bu Mac'te çalışır. Varsayılan olarak sohbet görünümünde (Agent SDK) açılır, istenirse terminalde (node-pty + xterm).
  - **Web**: claude.ai, hesaba özel çerez bölmesinde (`<webview partition="persist:chat-<id>">`).
- Hesap ayrımı `CLAUDE_CONFIG_DIR` ile yapılır: her hesabın kendi ayar klasörü var (`~/.claude-is`, `~/.claude-max`, `~/.claude-pro`). Boş bırakılan hesap varsayılan `~/.claude` klasörünü kullanır.
- Projede yalnız Emre ve Claude var. Görsel yön Emre'nin; hedef, Claude masaüstü uygulamasının sohbet düzenine yakın durmak (koyu tema, serif yanıtlar, toplu araç satırları, alttaki model/efor seçicileri, sağ yan panel). Renk ve yazı dili 2026-10-20'den beri "Gece ve Şampanya": oniks zemin, fildişi yazı, tek vurgu şampanya altını, başlıklarda Didot. Açık tema ("Gün ve Şampanya": fildişi kâğıt zemin, mürekkep yazı, koyulaşmış altın) aynı gün eklendi; seçim Görünüm → Tema ya da ayarlar penceresinden (Sistem / Koyu / Açık).

## 2. Çalıştırma

```bash
npm install          # ilk kez ya da bağımlılık değişince (Node 22.12+; Emre'de nvm varsayılanı 24)
npm start            # geliştirme: uygulamayı doğrudan açar
npm run check        # tüm JS dosyalarında sözdizimi kontrolü (saniyeler)
npm test             # uçtan uca test (sahte Claude CLI ile, ~20 sn)
npm run build:sim    # simülatör yardımcısını derler (Xcode + AXe gerekir)
bash kur.sh          # Mac uygulamasını paketler ve ~/Applications/Claude Panel.app'e kurar
bash kur.sh --dmg    # kurmaz; başka Mac'e verilecek dist/Claude-Panel-<sürüm>-<mimari>.dmg (imzasız, ad-hoc)
```

Uygulama açıkken `kur.sh` çalıştırılmaz; önce panel kapatılır (açık Claude oturumları sonlanır).

## 4. Doğrulama

1. Doğrulama yolu söylenemeyen iş başlamaz; doğrulanmamış iş bitmiş sayılmaz.
2. Her değişiklikte en az `npm run check`.
3. Arayüz ya da ana süreç davranışı değiştiyse `npm test`. Yeni bir davranış eklendiyse `tests/e2e.js`'e bir adım ve kesin bir `assert` eklenir; yeni adım bir kez bilerek bozulup kırmızıya döndüğü görülür.
4. Sahte CLI'nin gerçek Claude Code'dan farklı davrandığı yerler olabilir. SDK protokolüne dokunan değişikliklerde (yeni mesaj tipi, kontrol isteği) `node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts` tiplerine bakılır ve `fake-claude.js` güncellenir. Ardından Emre'den gerçek hesapla bir tur denemesi istenir.
5. Görünen değişiklikte `tests/out/` altındaki ekran görüntülerine bakılır.
6. Paketlemeyi etkileyen değişiklikte (`package.json`, `kur.sh`, yeni dosya yolu) `bash kur.sh` koşulur ve kurulan uygulama açılıp denenir.

## 5. Öğrenilmiş tuzaklar (değiştirmeden önce oku)

- **Agent SDK ayar klasörünü süreç başına bir kez okur** (`CLAUDE_CONFIG_DIR` memoize edilir). Bu yüzden `listSessions` / `getSessionMessages` ana süreçte çağrılmaz; her çağrı `scripts/sessions.mjs` ile, hesabın ortamıyla ayrı bir süreçte (`ELECTRON_RUN_AS_NODE=1`) yapılır. `query()` her oturum için ayrı Claude Code süreci açtığından ve `env` seçeneğini aldığından sorun değildir.
- **SDK `env` seçeneği ortamı tamamen değiştirir**, birleştirmez. Finder'dan açılan uygulamanın PATH'i kısa olduğu için `chat-main.js` → `loginEnv()` kullanıcının giriş kabuğunu (`$SHELL -l -i`) bir kez çalıştırıp gerçek ortamı alır. Terminal sekmeleri de `-l -i` ile açılır.
- **Giriş bilgileri hesap başına ayrı**: Claude Code macOS Anahtar Zinciri'nde `Claude Code-credentials-<ayar klasörü sha256'sının ilk 8 hanesi>` adını kullanır. Bunu SDK kodunda doğruladık.
- **İzin istekleri**: SDK'ya `canUseTool` verilir; arayüz kartı yanıtlanınca `chat:permissionReply` ile çözülür. `AskUserQuestion` cevabı `updatedInput.answers = { [soru metni]: "seçilen etiket" }` ile döner. `ExitPlanMode` onayından sonra mod `acceptEdits` ya da `default` yapılır.
- **Efor çalışırken** `query.applyFlagSettings({ effortLevel })` ile, başlangıçta `options.effort` ile verilir. Model başına desteklenen seviyeler `supportedModels()` → `supportedEffortLevels` alanından gelir.
- `settingSources: ['user','project','local']` ve `systemPrompt: { type:'preset', preset:'claude_code' }` verilir. Verilmezse proje `CLAUDE.md`'si, hook'ları ve izinleri yüklenmez.
- `allowDangerouslySkipPermissions: true`, sonradan "Tam yetki" moduna geçebilmek içindir; mod kendisi seçilmedikçe etkisi yoktur.
- **Paketleme `--no-asar`**: node-pty'nin `spawn-helper` dosyası ve SDK'nın platform ikilisi asar içinden çalıştırılamaz.
- **Electron 44 ve npm 11**: Electron 42'den beri kendini `postinstall` ile indirmez; ikili dosya ilk `require('electron')` / `electron .` çağrısında indirilir (`npm test`'in ilk koşusu "Downloading Electron binary…" der). npm 11 bağımlılık betiklerini yalnız `package.json` → `allowScripts`'te izinliyse çalıştırır; tek betikli paket node-pty, sürüme bağlı izinli (`node-pty@1.1.0`). node-pty yükseltilince `npm install-scripts approve node-pty` yeniden çalıştırılır, yoksa betik sessizce atlanır. Electron 44 Node 22.12+ ister; `kur.sh` bunu denetler.
- **Bildirimler** (main.js → `notify`): Electron 42+ macOS bildirimini `UNNotification` ile gösterir, imzasız (ad-hoc) uygulamada `failed` (`UNErrorDomain 1`) döner. Aynı deneme uygulamasıyla ölçüldü: Electron 38'de göründü, 44'te reddedildi. Reddedilince Dock simgesi zıplar ve okunmamış sayısını gösterir (`dockAlert`), pencere odaklanınca silinir. Geliştirme Electron'unda da reddediliyor (e2e'de sayı önceki adımlardan birikiyordu). Uygulama imzalanırsa balon kendiliğinden geri gelir.
- **claude.ai/code'daki "Local" seçeneği** yalnız resmi Claude masaüstü uygulamasında çalışır. Web görünümünde bu sayfaya gidilince "Yerel Code'a geç" şeridi çıkar.
- **Web girişi**: e-postadaki link Safari'de açılır. Doğrulama kodu girilir ya da link panelin adres çubuğuna yapıştırılır.
- **Artifacts görüntüleme** `artifact://view/<id>/<n>/` özel protokolüyle (standart + secure şema; `registerSchemesAsPrivileged` app hazır olmadan çağrılır). `srcdoc` kullanılmaz: iframe ana sayfanın CSP'sini miras alır ve artifact betikleri çalışmaz. Sayfa CSP'sinde `frame-src artifact:` ve `img-src artifact:` vardır. Göreli bağlantılar (`logo.png`) kaynak dosyanın klasöründen sunulur; ama yalnız varlık uzantıları (`MIME` listesi; `.json` yok), `realpath` ile çözülmüş ve klasörün içinde kalanlar. Sayfalar `CSP: sandbox` başlığıyla (`PAGE_SANDBOX`, görüntüleyici iframe'inin izinleriyle aynı) kökensiz sunulur. **Electron bu şemada CORS uygulamaz ve `Sec-Fetch-*`/`Origin` başlığı göndermez** (ölçüldü): sayfa betiği `fetch` ile sunulan her şeyi okuyabilir. Bu yüzden sınır sunucu tarafındadır: `.env`/`.json` gibi dosyalar hiç sunulmaz. Görüntüleyicideki bir sayfa, kimliğini bildiği başka bir artifact'i okuyabilir (kimlikler 48 bit rastgele; §7). `publish_artifact` izin sormadığı için `file_path` çalışma klasörüyle sınırlı. e2e'de ayrı adımları var.
- **Küçük resimler** görünmez, `offscreen` bir pencerede çizilip `capturePage` ile alınır; sırayla, sürüm başına bir kez. Kimse açmadan kendiliğinden çizildikleri için ayrı, bellekte bir oturumda (`artifact-thumbs`) çizilir: yalnız o an çizilen artifact (`thumbJob`) sunulur, ağ kapalıdır (`webRequest`); bilinen CDN'lerden (`THUMB_CDN`) yalnız betik, stil ve yazı tipi gelir. WebRTC `webRequest`'ten geçmediği için oturum erişilemeyen bir proxy'ye yönlenir (`DEAD_PROXY`, yerel adresler dahil, CDN'ler hariç) ve pencerede proxy'siz UDP kapalıdır; ikisi de gerekli (e2e'de ayrı ayrı bozuldu). DNS ön çözümleme gibi yan kanallar denenmedi.
- **Pencere sürükleme**: üst çubuk yok. `-webkit-app-region: drag` sekme şeridinde (`.tabbar`), Web araç çubuğunda (`.chat-toolbar`), kenar çubuğunun üst satırında (`.drag`) ve yalnız Artifacts sayfasında görünen `.main-drag` şeridinde. Bu bölgelerde tıklanan her öğe `no-drag` olmalı (styles.css: `button, input, select, textarea, a, summary, .tab, .art-card`); yoksa tıklama pencereyi sürükler. Sürükleme bölgesine tıklanacak yeni bir `div` eklenirse bu listeye eklenir. **Bölgeler belge sırasıyla üst üste konur** (sonraki öncekini ezer, `z-index` etkisiz): sürükleme şeridinin üstüne `position: fixed` ile binen bir düğme belgede şeritten **sonra** durmalı. Kenar çubuğu düğmesi `#app`'in başındayken `.drag` ve `.tabbar`'ın altında kalıyor, gerçek tıklamada pencereyi sürüklüyordu (2026-10-20). Playwright'ın tıklaması CDP'den gittiği için bunu yakalamaz; e2e düğmenin ortasındaki son bölgeyi ölçer (`toggleRegion`). Pencere düğmeleri `trafficLightPosition: {16, 18}` ile 48 px satırın ortasında. Hemen sağlarında sabit kenar çubuğu düğmesi (`#sidebarToggle`, `position: fixed`); kenar çubuğu kapalıyken (`body.sidebar-off`) pencerenin en üstündeki şeritler (`.tabbar`, `.chat-toolbar`, `.av-head`) soldan 112 px boşluk alır. En üste yeni bir şerit eklenirse bu kurala eklenir.
- **Ana pencere kendi sayfasından ayrılmaz** (`will-navigate`, main.js). Preload her sayfada çalıştığı için dış bir sayfa `window.panel`'i (terminal, dosyalar) alırdı. Claude'un Markdown'u `PURIFY` ile temizlenir (form, düğme, stil, `style` ve `id` özelliği yok; `class`'ta yalnız `language-*` kalır, panelin sınıflarıyla sahte kart çizilmesin; görev kutucukları için `input` kalır); CSP'de `form-action 'none'`. Playwright engellenen gezinmeden sonra tıklamalarda takılır; bu yüzden e2e'de o adım en sondadır.
- **`publish_artifact`**: `createSdkMcpServer` + `zod` ile her sohbete `mcpServers.panel` olarak verilir, `allowedTools` ile izin sormaz. Sahte CLI bu çağrıyı `mcp_message` kontrol isteğiyle taklit eder; yanıt `{ mcp_response }` içinde döner.
- Galeri yenilenirken açık görüntüleyici yeniden kurulmaz; kendini `refresh()` ile günceller (seçili sürüm/mod korunur).
- **Model listesi ve kullanım** `account:info` ile gelir (chat-main.js). Hesabın açık sohbeti varsa onun `q`'su kullanılır; yoksa mesaj göndermeyen, `persistSession: false` ve `settingSources: []` ile kısa ömürlü bir yoklama süreci açılır (token harcamaz). Sonuç önbellekte: modeller 10 dk, kullanım 60 sn. Kullanım SDK'nın deneysel `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET({ skipBehaviors: true })` (`get_usage`) çağrısından gelir; adı değişirse arayüz "bilgi yok" gösterir, SDK güncellenince ilk bakılacak yer burası. Claude Code giriş bilgisini süreç açılırken okur: girişten önce açılmış sohbet "plan yok" (`rate_limits_available: false`) döndürür. Bu durumda `probe()` taze bir yoklama süreciyle yeniden sorar.
- Yeni sohbet ekranındaki model/efor seçimi `chatPrefs`'e yazılır ve sohbet başlarken `--model=` / `--effort=` olarak gider. Sahte CLI `init` mesajında bu değerleri geri bildirir (gerçek Claude Code gibi).
- **Ekler** (`readAttachment`, renderer/chat.js): Electron 32+'da `File.path` yok; yol `window.panel.filePath(file)` (`webUtils.getPathForFile`) ile alınır, panodan gelen görselde boştur. Görsel → `image` bloğu (3,75 MB üstü küçültülür), küçük metin → içeriğiyle `<attached_file>` metin bloğu (gövdedeki aynı etiket `fileSafe` ile bozulur), diğerleri → yalnız yol. Ana süreç `cleanContent` ile yalnız `text`/`image` bloklarını geçirir. Bağlayıcı dizini ve ayarları hesabın Web görünümünde açılır (`openWeb`).
- Electron'da `window.prompt` yoktur; metin ve onay için `dialogModal()` (renderer/artifacts.js) kullanılır. `confirm` çalışır ama az kullanılır.
- **Panel genelindeki MCP sunucuları** (Blender, figma-console): her hesabın kendi `.claude.json` dosyasında genel (user) kapsamda durur. Bu yüzden her klasörde yüklenir. `~/.claude.json` dosyasında yoktur, panel dışındaki Claude Code oturumları etkilenmez. Yeni sunucu her hesap için `CLAUDE_CONFIG_DIR=~/.claude-<id> claude mcp add-json -s user <ad> '<json>'` ile eklenir; giriş yapılmamış hesapta da çalışır. `ayarlari-esitle.sh` yalnız `~/.claude.json`'dan kopyalar; bu sunucuları bilmez, ama var olanın üzerine de yazmaz. Resmi Figma gibi claude.ai bağlantıları ise hesabın claude.ai girişinden gelir; panel ayarı gerekmez.
- **Bağlayıcıları açıp kapama** (`mcp:list` / `mcp:toggle`, chat-main.js): ayrı panel ayarı yok. Claude Code'un `/mcp disable` kaydı kullanılır: hesabın `.claude.json` dosyasında `projects[<proje>].disabledMcpServers`. Proje anahtarı git köküdür (alt klasör değil; worktree'de ana depo), git dışında klasörün gerçek yolu (`projectKey`). Panel dosyaya doğrudan yazar. Claude Code yazmadan önce dosyayı yeniden okuduğu için bu değişiklik ezilmez (gerçek ikiliyle denendi). Açık sohbet varsa ayrıca `q.toggleMcpServer()` çağrılır. claude.ai bağlayıcılarının adları `claudeAiMcpEverConnected` alanından gelir.
- **Eklentileri yönet** (`plugins:list` / `plugins:toggle`): açık/kapalı durumu hesabın genel `settings.json` → `enabledPlugins` alanında, kurulu liste `plugins/installed_plugins.json`'da. `settings.json` symlink olduğundan (`~/.claude`) değişiklik bütün hesaplarda ve panel dışında geçerlidir. Yazarken `realpath` hedefine yazılır, yoksa atomik yazma symlink'i normal dosyaya çevirir. Açık sohbetlerde `q.reloadPlugins()` çağrılır.
- **Skill'ler** (`skills.js`; 2026-10-20'de gerçek CLI 2.1.300 ile girişsiz ölçüldü): liste mesaj göndermeyen kısa ömürlü süreçten (`initializationResult().commands`, kaynaklar `getContextUsage().skills.skillFrontmatter`; `--settings` ile `disableAllHooks` ve dosyalardaki bütün `skillOverrides` anahtarları `on`, `strictMcpConfig`). Komut açıklamasının sonundaki `(user)`/`(project)`/`(claude.ai sync)` atılır. `skillOverrides` anahtarı kişisel/proje skill'inde **klasör adıdır** (frontmatter adı değil; farklıysa `aliases`'ta); Claude Code claude.ai skill'inde iç adla sonra niteliksiz adla, yerleşikte adla bakar; eklenti skill'leri ayarı yok sayar. Panel genel `settings.json`'a yazar ve skill'in öbür adlarıyla duran kayıtları siler; klasörün `.claude/settings(.local).json`'u belirliyorsa kilitli. Claude Code'un `/skills` menüsü `.claude/settings.local.json`'a yazar. Açık oturum dosyayı izler, `commands_changed` (alan `commands`) yollar. claude.ai skill'leri girişsiz yüklenmediği için anahtar kuralları onlarda ölçülmedi. Sahte CLI skill'leri diskten kurar, ayar klasörünü `fs.watch` ile izler, yoklamayı `SKILLPROBE`, değişikliği `SKILLS <adlar>` diye günlüğe yazar.
- **Claude Code'un JSON dosyalarına yazarken** (`.claude.json`, `settings.json`) `readJsonForWrite` kullanılır: okunamayan dosyanın üzerine asla yazılmaz (Claude Code o an yazıyor olabilir; boş içerikle ezmek hesabın tüm proje kayıtlarını siler).
- **İzin sormayan MCP sunucuları** `config.json` → `autoAllowMcp`'tedir (varsayılan boş; `main.js` → `cleanMcpNames` yalnız sunucu adı biçimini alır, `chat-main.js` → `autoAllowTools()`). P8.2'ye kadar ürün kodunda sabitti (`blender`, `figma-console`, Emre'nin isteği); başka kullanıcılara da izinsiz kod çalıştırma veriyordu. Liste boşsa terminale `--allowedTools` hiç gitmez. Sohbete SDK `allowedTools` (`mcp__<sunucu>` tüm araçları kapsar), terminaldeki `claude`'a `--allowedTools` olarak gider. Ortak `settings.json`'a yazılmaz: o dosya `~/.claude`'a bağlı, panel dışındaki oturumları da etkiler. Yönetilen ayarlarda `allowManagedPermissionRulesOnly` açılırsa `--allowedTools` yok sayılır.
- **iOS simülatörü** (`simulator.js`, `native/simhelper.swift`): `simctl io screenshot` ve AXe'nin hazır komutları ölçüldü, yavaş kaldı (AXe `tap` ~1,2 sn, `stream-video` mjpeg ~4 kare/sn). Bu yüzden sürekli açık bir Swift yardımcısı AXe'nin `FBSimulatorControl` çatılarına bağlanır: kareler framebuffer'dan (IOSurface, yalnız değişince, en çok 30/sn, 750 px genişlikte JPEG), dokunma `FBSimulatorHID` ile (~1 ms). Çerçeve: 1 bayt tür (`F` kare, `J` JSON) + 4 bayt uzunluk + veri. AXe'nin Swift arayüzü olduğu gibi derlenmez: modülle aynı adlı `FBSimulatorControl` sınıfı yüzünden `FBSimulatorControl.FBx` ve `IOSurface.IOSurface` nitelemeleri `build-simhelper.sh`'te sed ile atılır, Xcode'un özel `CoreSimulator` modülü yerine `native/CoreSimulator/` altında yalnız sınıf adları olan bir taslak verilir. Yardımcı çatıları `rpath` ile `$(brew --prefix axe)/libexec/Frameworks`'ten yükler; AXe kaldırılırsa simülatör "AXe kurulu değil" der. AXe güncellemesinde arayüz değişirse ilk bakılacak yer bu betik.
- Simülatörde **koordinatlar nokta (point)** cinsinden (iPhone 17: 402×874). Claude'a giden ekran görüntüsü de nokta çözünürlüğüne küçültülür; görüntüdeki piksel = dokunma koordinatı. Sürükleme, aynı yönle (`down`) art arda gönderilen dokunmalarla yapılır (FBSimulatorHID'de ayrı "move" yok); iki parmak (`touch2`) da öyle.
- **Yön** (ölçüldü): döndürünce ekran karesi ve HID koordinatları fiziksel (dikey) düzlemde kalır, iOS içeriği yan çevirip çizer. Panel kareyi tuvalde döndürür (`landscapeLeft` = saat yönünde, `landscapeRight` = tersine), Claude'a dik ekran görüntüsü gider (`turn`), görünen koordinatlar `toPhysical()` ile fiziksel düzleme çevrilir. Bağlanınca cihaz dikeye alınır (önceki oturumdan yan kalmış olabilir). iPhone ana ekranı yatay dönmez; yatayda yan görünmesi doğrudur.
- **Klavye düzeni ve Türkçe yazı** (simulator.js → `typeText`, `LAYOUTS`): HID klavyesi tuşun *yerini* gönderir, karakteri iOS kendi donanım klavye düzenine göre seçer. Emre'nin simülatörü Türkçe Q (`tr_TR@sw=Turkish-Q;hw=Automatic`): ABD düzenine göre gönderilen `i` → `ı`, `;` → `ş`, `'` → `i` yazıyordu (ölçüldü). Bu yüzden her karakter simülatörün o anki düzeninde onu yazan tuşa + ⇧/⌥'e çevrilir; düzen `simctl spawn <udid> defaults read com.apple.keyboard.preferences KeyboardLastUsed`'dan (yoksa `AppleKeyboards`'un ilki) okunur, 5 sn önbellekte, ilk okuma bağlanınca. Türkçe Q tablosu gerçek simülatörde her tuş × değiştirici basılarak ölçüldü; ölü tuşlar (`` ` `` `´` ve ⇧3 `^`) ardından boşlukla gider. ABD tablosu standart düzen (simülatörde ölçülemedi: donanım klavyesi bağlıyken iOS'ta düzen değiştirilemiyor). Tablosu olmayan düzen ya da düzende olmayan karakter (emoji) `simctl pbcopy` + ⌘V ile gider. **Pano son çare**: iOS her yapıştırmada "… CoreSimulatorBridge'den yapıştırmak istiyor" diye izin sorar ve yanıtlanana kadar gelen tuşlar kaybolur (eskiden her Türkçe harf böyle gidiyordu, "Türkçe yazılmıyor" şikâyetinin asıl nedeni). Mac'ten ⌘V de bu yüzden tuşlarla yazılır. `pbcopy`'ye `LANG=en_US.UTF-8` verilmezse metin MacRoman sanılıp bozulur. Yardımcının `text` komutu (ABD düzeni) artık panelce kullanılmaz. Bölmede tuşlar ve Claude'un yazıları tek bir sırayla (`enqueue`) gider.
- **Simülatörde özel tuşlar basılı tutulur** (oklar, ⌫, ileri sil, Enter, Tab, Esc; ⇧/⌥ birlikte): bölmede keydown → yardımcıya `{cmd:'key', phase:'down'}`, keyup → `phase:'up'`; `e.repeat` gitmez, tekrarı iOS yapar (`simulator.js` → `holdKey`/`releaseKey`). Sebep: Safari (WebKit) alanlarında hemen bırakılan ok, ileri sil ve ⌥⌫'den sonraki ~100–300 ms içinde gelen tuşlar düşüyordu (ölçüldü; yerel UITextField'da yok). Bırakma en erken basmadan `KEY_MIN_HOLD` (100 ms) sonra gider; ardındaki tuşlar bunu sırada bekler. iOS uzun basışta ~400 ms sonra her ~100 ms'de yineler; yineleme bırakmaya denk gelirse ~25 ms sonra gelen tuş da düşebiliyor (ölçüldü, 30 denemede 1). Bu yüzden `KEY_REPEAT_DELAY` (350 ms) ve üstü basışlardan sonra sıradaki girdi 100 ms daha bekler. Odak kaybında, ⌘'ye basılınca (Mac ⌘ basılıyken keyup göndermez), bölme kapanınca ve bağlantı kesilirken basılı tuşlar bırakılır; yoksa iOS tuşu sonsuza dek tekrarlar. - **Tarayıcı** (`browser.js`, `renderer/browser.js`): her sohbetin yanında bir `<webview partition="persist:browser-<hesap>">`. **Sekmeler**: bölmede birden çok sekme açılabilir (adres çubuğunun yanındaki "+"; şerit yalnız 2+ sekmede görünür, son sekme kapanınca bölme kapanır), her sekme ayrı webview; gizli sekme `display:none` değil `.br-frame.off` (görünmez, mutlak). Açılır pencereler hâlâ aynı sekmede açılır. Arayüz etkin webview'in kimliğini `browser:attach` ile bildirir; ana süreç sahibini (`hostWebContents`) ve bölmesini denetleyip sayfayı `webContents.debugger` (CDP) ile sürer. Tıklama/tuş `Input.dispatch*` ile (pencere odağı gerekmez); ⌘A/C/V/X/Z CDP'de `commands` verilmeden çalışmaz. Ekran görüntüsü sayfanın CSS piksel boyutuna küçültülür (görüntüdeki piksel = tıklama koordinatı). **Webview'in zemini saydamdır**: `Emulation.setDefaultBackgroundColorOverride` beyaz verilmezse zeminsiz sayfanın JPEG görüntüsü siyah çıkar (ölçüldü, e2e'de ayrı assert). **`allowpopups` gerekli**: yoksa `window.open` hiç tetiklenmez ve `setWindowOpenHandler`'a gelmez; işleyici adresi aynı bölmede açar. İndirme `will-download`'da `preventDefault` ile iptal, izinler (kamera, konum, bildirim…) kapalı, yalnız http/https ve `about:blank`. `main.js` → `will-attach-webview` bütün webview'lerden preload'u atar, yalnız `persist:chat-*` / `persist:browser-*` bölmelerine izin verir; tarayıcı webview'leri `web-contents-created`'da claude.ai kurallarından ayrılır (`isBrowserSession`, bölmenin `storagePath`'ine bakar).

Kullanıcının adres çubuğundan açtığı site de izinli sayılır (`browser:userNav`). Kartta "Bu oturumda hep izin ver" yoktur: SDK'nın araç düzeyindeki kuralı site denetimini atlatırdı. "Tam yetki" modunda `canUseTool` çağrılmaz, her site açılır.

Kullanıcının sayfadaki tıklaması/tuşu ve adres çubuğu, geri/ileri/yenile (`browser:userNav` + webview kimliği) `tainted`'ı kaldırır. **Claude'un CDP girdisi de `input-event` üretir** (ölçüldü, CDP yanıtından önce gelir); bu yüzden araç çalışırken (`page.acting`) gelen girdi kullanıcının sayılmaz. `loadURL` `will-navigate` üretmez (adres çubuğu ve Claude'un `navigate`'i), yalnız yönlendirmesi `will-redirect`'e düşer. Claude'un çalışan `navigate`'i hedef kökeni izinliye ekler ("Tam yetki"de site içi gezinme kırılmasın). `fetch`/görsel/alt çerçeveyle veri gönderimi ağ düzeyinde engellenmez (yerel uygulamalar CDN'den yükler); README'de yazılı.

Çıktı beklemesi ana süreçte pty verisinin zamanına bakar (`noteData`). İzin: `list`/`read` sormadan, `run` her seferinde, `stop` Claude'un o sohbette açmadığı sekmede kartla; kartlarda "hep izin ver" yok.
